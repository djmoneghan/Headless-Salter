# PDF Download Plan — web_sterilizer v0.2

## Summary

Add a `download_pdf` MCP tool that fetches a raw PDF from an allowlisted URL and saves it to a configured local directory. The calling agent receives a file path and uses a separate tool for text extraction. No PDF parsing occurs inside `web_sterilizer`.

---

## Motivation

The existing `fetch_web_content` tool sterilizes HTML into plain text to defend against prompt injection. PDFs are binary files — text sterilization is not applicable. Rather than embedding a PDF text extractor (and its attack surface) into this tool, the raw file is written to disk and a separate, dedicated tool handles extraction and conversion to the agent's markdown format.

---

## What Changes

| Component | Change |
|---|---|
| `sterilizer_config.json` | Two new keys: `allow_pdf_download` (bool, default `false`) and `pdf_download_dir` (string path) |
| `web_sterilizer.py` | New MCP tool `download_pdf` + two new stage functions |
| `tests/test_pdf_download.py` | New test file covering all required scenarios |
| `requirements.txt` | No new dependencies |

### What Does NOT Change

- `fetch_web_content` and its 10-stage sterilization pipeline
- `stage_validate_url` and `stage_fetch` (reused as-is)
- All existing tests

---

## Pipeline

```
1. Check allow_pdf_download == true in config; reject immediately if false
2. Validate URL            (stage_validate_url — unchanged: scheme, SSRF, allowlist)
3. HTTP fetch              (stage_fetch — unchanged: timeout, redirect limit, byte cap)
4. Verify Content-Type header == application/pdf; abort and delete any partial data if not
5. Write bytes to pdf_download_dir with a generated filename
6. Return structured response with file_path, file_size_bytes, audit_log
```

Stages 4–10 of the text sterilization pipeline (hidden content removal, whitespace normalization, pattern scan, instruction verb filter, truncation, salt wrap) do **not** run. There is no text to scan.

---

## Security Constraints

### Filename Generation
The filename is always `{iso_timestamp}_{random_hex_8}.pdf`, generated by the tool. It is never derived from the URL path, query string, `Content-Disposition` header, or any agent-supplied input. This prevents path traversal attacks via crafted URLs.

### Destination Directory
`pdf_download_dir` is set by the operator in `sterilizer_config.json`. The agent cannot specify or influence the destination path — the `download_pdf` tool accepts only a URL parameter. If the directory does not exist or is not writable, the tool fails closed.

### Content-Type Enforcement
The `Content-Type` response header must be `application/pdf` (or `application/octet-stream` with a `.pdf` extension as a fallback, operator-configurable). If the server returns any other type — including `text/html` — the download is aborted before any bytes are written to disk.

### Byte Cap
`max_response_bytes` from the existing config applies. Responses exceeding this limit are aborted before writing. No partial files are left on disk.

### allow_pdf_download Default
`allow_pdf_download` defaults to `false`. The `download_pdf` tool returns an immediate `success=False` error unless the operator has explicitly set it to `true`. Enabling it does not relax any other constraint (SSRF block, allowlist, size cap all remain active).

### No Execution
The tool writes bytes to disk only. It does not open, parse, render, or execute the PDF in any way.

---

## Configuration

Add to `sterilizer_config.json`:

```json
{
  "allow_pdf_download": false,
  "pdf_download_dir": "./downloads"
}
```

`pdf_download_dir` may be an absolute or relative path. Relative paths are resolved from the config file's directory.

## MCP Tool Schema

```python
@mcp.tool()
def download_pdf(
    url: str,
    purpose: str = "",
) -> dict:
```

### Return Value

```python
{
    "success": bool,
    "file_path": str,        # Absolute path to saved file, or "" on failure
    "source_url": str,       # Final URL after redirects
    "fetch_timestamp": str,  # ISO 8601
    "file_size_bytes": int,  # 0 on failure
    "audit_log": dict,
    "error": str | None
}
```

### audit_log fields

```python
{
    "requested_url": str,
    "final_url": str,
    "fetch_timestamp": str,
    "purpose": str,
    "file_size_bytes": int,
    "content_type": str,     # As reported by server
    "generated_filename": str,
    "error": str | None      # Present only on failure
}
```

## Test Requirements

- `allow_pdf_download: false` → immediate rejection, no file written
- Unlisted domain → rejected (allowlist enforcement)
- SSRF address → rejected
- Non-PDF Content-Type → aborted, no file written to disk
- Valid PDF response → file written, path returned, file_size_bytes correct
- Response exceeds `max_response_bytes` → aborted, no file written
- `pdf_download_dir` does not exist → fails closed, no crash
- Generated filenames are unique across consecutive calls
- Agent cannot influence filename (url path components not used)
- `purpose` appears in audit_log

---

## Out of Scope

- PDF text extraction or parsing of any kind
- Password-protected PDFs
- Scanned / image-only PDFs
- Embedded attachments within PDFs
- Streaming / partial downloads
- Any modification to `fetch_web_content` or its pipeline
